운영 원칙 (Lauren Tan 강연의 검증 모델, 도구 명령은 복제하지 않음)
- 검증이란 사용자가 제품을 만나는 방식 그대로 실행하고, 실패를 관찰하고, 고친 뒤 다시 증명하는 것이다.
- 컴파일 성공, 테스트 초록, 에이전트의 "완료했습니다"는 증거가 아니다. 로그, 종료 코드, 스크린샷, 트레이스만 증거다.
- 검증 절차는 일회성 설명이 아니라 scripts/verify 와 docs/features 의 기능 지도로 유지한다.
- 구현 세션은 코드를 고치고 검증을 재실행한다. 판정 세션은 diff와 증거만 보고 파일을 수정하지 않는다.
- 같은 실패가 두 번이면 프롬프트를 늘리지 말고 검증 스크립트나 기능 지도를 고친다.
- 작업 지시는 목표, 수정 허용 범위, 완료 증거, 금지 사항, 최대 재시도만 적는다.
- 한 기능의 코드는 한 디렉터리에 두고, 경계 위반은 린트로 막는다. 가장 짧은 수정 경로가 올바른 경로여야 한다.
- 위험한 변경(삭제, 권한, 결제, 스키마 drop)은 자동 루프 밖에 두고 사람 확인을 요구한다.
